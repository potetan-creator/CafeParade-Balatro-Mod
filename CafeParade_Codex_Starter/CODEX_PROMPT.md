# Codexに渡す依頼文 — Café Parade Balatro MOD v0.1

あなたはBalatro/Steamoddedに詳しいLua開発エージェントです。今開いているフォルダにある `CARD_SPEC.md`、`ASSET_GUIDE.md`、`COLOR_PALETTE.json` を必ず最初に読んでください。日本語で作業内容を報告してください。

## ゴール
アイドルマスター SideM の「Café Parade」5人とサタンをモチーフにした **6枚の新規ジョーカー** を Balatro に追加する MOD `CafeParade` を制作してください。通常のアンティ8でも活躍し、デッキ育成・カード再発動・永続×倍率によりエンドレスでも選択肢になる能力を実装します。元ゲームのデータを直接書き換えず、Lovely + Steamodded 用の Lua MOD として完成させてください。

## 環境・API
- 開発対象: Windows版 Balatro / 最新安定 Lovely + Steamodded。開発時に実際のインストールバージョンを確認し、そのバージョンの公式 docs.smods.dev / 参照実装に従う。
- `SMODS.Joker`、`SMODS.Atlas`、日本語ローカライズ `localization/ja.lua` を使用する。必要に応じて `localization/en-us.lua` も用意。
- メタデータ、MOD ID、ロード方法は現行公式ドキュメントに合わせる。推測のAPI、存在しない関数を作らない。
- 書き込むのはこのMODフォルダ内のみ。ユーザーのセーブデータや本体ファイルを無断変更しない。
- `assets/1x/cafeparade_jokers.png` (426×95) と `assets/2x/cafeparade_jokers.png` (852×190) は **すでに用意した本物の仮画像**。このアトラスをそのまま使用する。`SMODS.Atlas` の `px=71, py=95`、`pos={x=0..5,y=0}` は `ASSET_GUIDE.md` の対応表に従う。画像生成は不要。
- 絵とコードを分離し、将来はユーザーが `art/source/{id}.png` を置き換え `python tools/build_atlas.py` で同じアトラスを再生成できるようにする。

## 必須機能
1. `CARD_SPEC.md` の6枚の効果を省略なく実装。コード中の数値は一か所の `config.lua` で調整可能にする。
2. 5人のユニーク所持数を返す共通関数を作る。サタンは所持数に含めない。重複、無効化（debuff）、Blueprint/Brainstormなどのコピー処理は仕様書どおり。
3. 成長値はジョーカー個体に保存し、途中セーブ→復帰で維持する。ラウンド・ブラインド単位の発動フラグも意図した範囲で管理。
4. スコア計算時の効果、追加発動、金銭付与、消耗品生成、カード強化をそれぞれ正しいコンテキストで処理する。
5. サタンのジョーカー枠+1は所持中のみ、売却・破壊・無効化で必ず取り消し、再有効化・セーブ復帰時に二重適用しない。コピージョーカーから枠増加は生じない。
6. 神谷のワイルドカード・スメアードジョーカー・スート判定は `CARD_SPEC.md` の仕様を実装する。難しい場合は無言で簡略化せず、代替案と挙動差を報告。
7. 日本語・英語で効果説明を表示。実際の状態（現在の×倍率、メンバー数、使用済み回数）をツールチップに表示できる範囲で反映。長文によるUIはみ出しを防ぐ。
8. 将来のカード追加に対応できるよう、各ジョーカー実装を分割し、共通ロジックを独立させる。
9. `README.md` に Lovely/Steamodded導入方法、Windows の `%AppData%\Balatro\Mods` への配置先、画像差し替え方法、既知の制約を日本語で書く。
10. 制作終了時に全ファイル一覧、実装済み機能、実行した検証、未検証機能、ゲーム内での手動テスト手順を報告する。実ゲーム起動で検証できない場合は「未検証」と明記する。

## 優先度と開発順
A. MODの認識・仮画像6枚・日本語名表示
B. 6枚それぞれの能力を単独で機能させる
C. 他メンバー間の連携、vanilla Jokerとの互換性
D. セーブ/ロード、Blueprint/Brainstorm、debuff、レッドシール、特殊カードなどの検証
E. バランス調整。仕様書の初期数値を勝手に変えず、提案は別途書く

## 完了条件
- 6枚がコレクションに現れ、適正なレアリティ・説明・仮画像を持つ。
- スコア・お金・タロット生成・変化・再発動・永続成長・追加枠の全効果が狙いどおり発動。
- 同じジョーカー/Blueprintのコピーを含め、無限再発動や成長値の二重付与がない。
- テスト計画を `TEST_PLAN.md` に記載し、可能なテストは実行する。
